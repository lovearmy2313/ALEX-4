ALEX CLOUD + MOBILE PREPARATION (NO .env INCLUDED)
=================================================

WHAT THIS PACKAGE CHANGES
- Keeps the existing Flask routes, web UI, and feature modules.
- Adds a production Gunicorn start command for Render.
- Makes SQLite memory and generated projects use ALEX_DATA_DIR when configured.
- Stores the Flask session signing key on the persistent data disk when no key is supplied.
- Enables Secure session cookies on Render.
- Fixes Android APK CI to build from alex_android/.
- Android WebView now rejects invalid/self-signed HTTPS certificates and no longer allows cleartext HTTP.

IMPORTANT: NO .env FILE IS INCLUDED. Do not upload a .env file to GitHub.

CLOUD HOST
This package is prepared for Render. The Blueprint uses a paid Starter web service and a
1 GB persistent disk so alex_memory.db and generated projects survive redeploys/restarts.
Do not create/activate the service until you have reviewed Render's current price and approved
any charge. A free ephemeral service is not suitable for keeping ALEX's SQLite memory.

DEPLOY STEPS (after reviewing cost)
1. Create a PRIVATE GitHub repository for ALEX.
2. Upload the contents of this folder to the repository root. Keep render.yaml at the root.
3. Confirm .env, .env.* (except the harmless .env.example template), alex_memory.db,
   and .alex_flask_secret are not committed. .gitignore excludes these local files.
4. In Render, choose New -> Blueprint and connect the private repository.
5. Review the service and persistent disk costs before approving creation.
6. In Render environment settings, provide GROQ_API_KEY and a strong unique ALEX_PASSWORD.
   FLASK_SECRET_KEY is generated by the Blueprint. Do not paste secrets into chat or GitHub.
7. Deploy. When live, test https://YOUR-SERVICE.onrender.com/health and then
   https://YOUR-SERVICE.onrender.com/app/ . The health endpoint is intentionally public and
   returns status metadata only; app features still require ALEX login.
8. Keep the local alex_memory.db as a backup. Do not push it to a public repository. We will
   migrate it to the persistent cloud disk separately after the cloud service is created.

ANDROID APK
- The Android project is in alex_android/.
- Push the project to GitHub. The workflow .github/workflows/build-apk.yml builds a debug APK.
- Open the repository's Actions tab, run "Build ALEX Android APK", and download the
  ALEX-Android-APK artifact after the workflow succeeds.
- On first app launch, paste https://YOUR-SERVICE.onrender.com/app/.
- This is a debug/test APK, not a Play Store-signed release APK.

IPHONE
- The current Android project cannot produce an iPhone IPA.
- iOS packaging requires a separate iOS target and a Mac with Xcode for signing/building.
- After the cloud URL is available, create the iOS wrapper and configure iOS privacy prompts.
  An IPA cannot be signed/built from this Windows-only project environment.

FEATURES / CLOUD LIMITATIONS
- ALEX's AI/API features, login, web UI, memory, tasks, skills, and server-side features can
  run on the cloud, subject to their external API keys and host resources.
- Windows desktop control (mouse, keyboard, local apps, local screenshots, local files) cannot
  run on a Linux cloud server. Keep a trusted Windows companion/local agent on the PC for those
  actions; do not expose an unauthenticated remote-control port to the public internet.
- Phone calls/SMS through Twilio need separate credentials and provider setup. Android native
  permissions do not automatically make iOS call/SMS/contact features available.

VALIDATION NOTE
The source was syntax-compiled with Python. A runtime import test could not complete in this
workspace because the edge-tts dependency is not installed here. Render installs requirements.txt
at deploy time. Re-run /health and /app/ checks after deployment.
